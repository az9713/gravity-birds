1. What you asked for

You wanted an original puzzle game in the spirit of Snakebird: grid-based, multi-segment creature, gravity after moves, fruit that grows the body, exit after collecting fruit, undo/restart — inspired by, not a clone of commercial IP.

Constraints that shaped the run:

  • Build it with Cursor in the loop (non-negotiable).
  • Prefer a real engine project you could open and play, not a throwaway web mock.
  • Keep it original: no Snakebird art, levels, characters, or trademarks.

The working title that landed was Gravity Birds. The Grok Bot team treated that as the product name; the remote repo Cursor spun up did not use that name (more on that below).

3. Non-negotiable: must use Cursor

The constraint was satisfied by launching a Cursor Cloud Agent against a new Origin repository. That is a valid Cursor path. It is not the only one.

Also would have counted: creating a local folder, opening it in the local Cursor IDE, and building there. “Must use Cursor” ≠ “must use Origin cloud agents.” The team picked the cloud path because it could scaffold a full Godot tree without Godot installed on your machine yet.

4. Platform choice: Godot 4

After a short platform check with you, the team settled on Godot 4 (target 4.3, GDScript). Reasons that mattered in practice: free, open, good for 2D grid puzzles, easy to open later on a laptop, no Unity license dance.

Important context: you did not have Godot installed yet when the cloud agent ran. So the first playable artifact lived in a remote repo and a remote agent workspace — not in a folder you could double-click. Editor play (F5) only becomes real after install + clone + Import.

5. Cursor Cloud Agent on Origin

Devin launched a Cloud Agent with new_repo (private Origin). Cursor auto-named the repo something like tmp-… — not “Snakebird” and not “Gravity Birds.” That naming choice is a recurring source of “where did it go?”

  • Engine: Godot 4.3 project (project.godot, scenes, scripts, level resources).
  • Spec: Rex’s simulation-order checklist injected mid-build (move → push → grow → gravity → hazards).
  • Content: five original levels, undo (Z), restart (R), menus / level select.
  • Web: agent attempted HTML5/web export (folder can look “done” even when browser play is incomplete — see unknowns).

Agent sessions show up under URLs shaped like cursor.com/agents/bc-…. The Origin codebase itself is a different surface (cursor.com/codebase/…). Neither magically appears as a row under local Cursor “home” until you clone.

6. The confusion wall — UNKNOWN UNKNOWNS

This is the section that usually gets papered over in “we shipped a game” writeups. Most of the frustration was not Godot — it was where state lives and what words like Cursor / Origin / Agents actually point at.

Origin repo ≠ folder on This PC

Cloud Agent writes into an Origin-hosted git remote and a remote workspace. Your laptop’s disk is empty of that project until someone clones it. Local Cursor’s home / recent list only shows local folders you have opened. No clone → nothing to list.

Auto-generated Origin name is easy to miss

Searching the UI or your memory for “Snakebird” or “Gravity Birds” will miss a repo named like tmp-…. The product name and the remote name were never the same string.

No obvious “Agents” menu on the IDE home screen

If you open the desktop IDE and look for a big Agents tab on the welcome screen, you may not find one. Practical paths: open cursor.com/codebase or the agent URL (cursor.com/agents/bc-…) in a browser while signed in.

Cloud Agent writes remotely; local IDE does not “see” Origin

There is no ambient sync that materializes Origin files into the IDE. Clone (or download) is the bridge. Until then, local Cursor and Origin are strangers.

“Must use Cursor” ≠ “must use Origin cloud agent”

Alternative that also satisfied the constraint: empty folder under Projects → Open Folder in local Cursor → build there. The team chose cloud for bootstrap speed without a local Godot install; that choice created the visibility gap.

Public GitHub create can 403 on a PAT while private create works

When re-homing off Origin, creating a public GitHub repo with a personal access token can fail with 403 even though creating a private repo with the same token succeeds. Scope / org policy / default visibility — whatever the root cause, the workable path was private gravity-birds.

Origin git HTTPS may reject tokens until origin auth login

Pushing or pulling Origin over HTTPS with a generic token can fail until Cursor’s Origin auth flow is happy (origin auth login or equivalent). The practical workaround used here: reconstruct / push the tree to GitHub, then clone GitHub onto the laptop. Origin remained the birthplace; GitHub became the laptop-friendly home.

Web export folder can exist without a playable wasm/pck

An export/ tree (or partial export) can exist while the browser build is missing critical artifacts (.wasm, .pck, etc.). Opening HTML then fails; Godot editor F5 still works. Do not treat “export folder present” as “web build ships.”

Inspired-by ≠ clone

Rex’s checklist and the agent prompt both insisted: no commercial Snakebird assets, levels, characters, or trademarks. Gravity Birds is an original grid-gravity snake-creature puzzle with its own name and levels.

  3. Research Rex produced a public-source mechanics checklist (simulation order, fruit, exit, hazards, undo) — original game only.

  5. Inject Mechanics checklist injected into the running agent so early code would not drift from the v1 rules.
  6. Build Agent implemented Godot 4.3 project: core loop, 5 levels, UI, undo/restart; attempted web export.
  7. Visibility wall Local Cursor home showed nothing; Origin name ≠ product name; agent URL / codebase URL needed in a browser.

  9. Laptop Clone to <UserProfile>\Projects\gravity-birds; open via File → Open Folder (Cursor and/or Godot Import).

8. GitHub re-home + laptop pull

End state for this journey (narrative stops here on purpose):

In Cursor: File → Open Folder on the Projects clone. In Godot: Import → select project.godot in that same folder.

9. How to play now

  1. Install Godot 4.3+ if you have not already.
  2. Import project.godot from <UserProfile>\Projects\gravity-birds.
  3. Press F5 (or the Play button) in the editor.

Controls

  • WASD or arrow keys — move the creature’s head
  • Z — undo
  • R — restart level

Prefer editor play over the web export until you have verified a full HTML5 export (templates installed, .wasm / .pck present, served over http://localhost, not file://).

10. Open leftovers / honest gaps

  • Web export reliability: treat browser play as best-effort until you re-export from a local Godot with templates installed and confirm artifacts.
  • Origin vs GitHub: two remotes may exist; day-to-day work should use the GitHub remote you can clone and push without Origin auth friction.
  • Level depth: five levels is a vertical slice, not a commercial campaign. Difficulty / teaching curve can still be tuned by hand.
  • Art: procedural / geometric placeholders — intentional originality, not final polish.
  • No Godot on the cloud path for you: the agent could headless-tool on its machine; your playtest path was always “install Godot locally after clone.”
  • Discovery UX: product name, Origin tmp-… name, and agent bc-… id are three different strings — bookmark the ones you care about.

11. Glossary

Origin
Cursor’s hosted git / codebase surface where Cloud Agents can new_repo and push. Lives in the cloud; not a folder on This PC until cloned elsewhere.
Cloud Agent
A Cursor agent that runs remotely against a repo/workspace (URL pattern cursor.com/agents/bc-…). Writes remotely; does not auto-mount into the local IDE.
Grok Bot team
The multi-bot roster (Chief orchestrating specialists like Devin and Rex). Bots share a box filesystem with each other; they do not share your laptop desktop. For this job: Chief + Devin + Rex only.
Local Cursor
The desktop IDE on your machine. Home / recents list local projects you opened. Opening a cloud-built game requires a local clone (or other download) first.
PAT 403
Personal Access Token rejected by GitHub for an operation (here: public repo create), while another operation (private repo create) with the same token may still work. Symptom of scope or policy — not “GitHub is down.”
